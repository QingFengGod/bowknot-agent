## 1. 简介

把 008 的任务组从会话内卡片提升为全局可管理的任务实体：左栏新增「任务」独立模块，提供任务组列表、状态筛选、任务与汇报详情、组级生命周期操作（确认 / 放弃 / 取消全部 / 继续已中断 / 终止 / 重试 / 删除 / 批量清理），并补齐 008 遗留的已中断继续与终止、任务删除、任务总量上限。任务汇总落盘到任务组，任务中心不依赖会话存储；schema 升到 2，兼容读取 schema 1。

不做生成任务接入、通知联动、执行中暂停、审批、费用金额与并行多计划；任务中心只展示 Agent 任务。

> 需求 v0.2 起，本计划的任务中心由 014–016 替代。

## 3. 实施顺序

`T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8`

先定汇总落盘与 schema 兼容（T1），它决定列表与详情能否脱离会话；总量上限与清理是删除操作的前置（T2）；恢复与终止的纯状态推导（T3）被调度器与页面共同依赖，先于编排（T4）；编排稳定后接共享装配（T5），最后做页面与操作（T6、T7），收尾自检与文档（T8）。

## 4. 实施总结

- 产出：左栏新增「任务」模块（`internal/task/page.go`）；任务组详情含状态、汇总、逐条任务汇报与错误；组级操作覆盖确认 / 放弃 / 取消全部 / 继续已中断 / 终止 / 重试 / 删除 / 批量清理；点击「打开会话」跳回发起会话。`task.Group` 增 `summary` 且 schema 2 兼容旧文件，汇总写回任务组；单文件总量上限 200，超限拒绝新建并在会话中提示清理。
- 装配：任务中心与助手页共享同一个 `task.Store` 与 `Dispatcher`，由 `internal/app` 注入 `taskActions` 适配器、会话标题查询与模块跳转；后台保存失败同时写入两页提示。
- 自检：`go build ./...`、`go vet ./...`、`go test ./...` 通过，`gofmt -l .` 无输出。新增测试覆盖 schema 1 读取、总量上限、终态清理、继续 / 终止状态推导、调度器恢复只执行未完成任务、删除与清理保护、超限拒绝派发、任务中心列表 / 筛选 / 详情 / 二次确认。
- 偏差：任务中心只支持按组确认与重试，不支持执行中暂停与审批；列表暂不展示费用金额（沿用用量只存原始记录的决定）；单派发槽限制继续沿用 008。
- 遗留：真实窗口下的列表滚动手感、长汇总文本换行与删除确认弹层位置待人工验收；macOS 未实机验证。
