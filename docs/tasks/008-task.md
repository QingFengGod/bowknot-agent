## 1. 目标

### 1.1 本次交付

1. `internal/task`：任务组与任务结构、状态机、JSON 原子落盘、重启恢复为「已中断」、并发调度。
2. `internal/agent` 扩展：子 Agent 定义与存储（`subagents.json`）、主 Agent 规划调用、确认卡片、派发编排、汇总。
3. 界面：左栏 Agent 列表加入子 Agent 与新建入口；主 Agent 与子 Agent 使用同一行布局，点击行可选中该 Agent 直接对话（会话按 Agent 隔离）；会话消息流内任务卡片（待确认 / 执行中 / 完成 / 失败 / 取消 / 中断）；子 Agent 新建与编辑弹窗、删除确认。
4. 输入区新增「任务模式」开关：关闭为 007 普通对话，开启后发送走规划流程。
5. 状态联动：网关不可用、无启用子 Agent、`chat` 无目标时禁用派发并说明原因。
6. 用量关联：`gateway.UsageRecord` / `ChatRequest` 增加可选 `task_id`（只增不改），任务调用带 `task_id` 与会话 ID。
7. `internal/app` 装配任务目录与任务存储；退出时取消运行中的任务组。
8. 单元测试、自检与人工验收步骤；回写 requirements 与 005 / 006 后续计划候选。

## 2. 前置状态与 mygo API 核实

007 已交付：`agent.Store`（会话 JSON、原子写、损坏跳过）、`agent.Runner`（50ms 节流流式、单生成、中止、重新生成）、`agent.Page`（三栏、会话面板、`ui.ComposerView`）。`internal/task` 为空目录。`gateway.Service.Chat` 支持 `ProviderID` / `Model` 定向、`Stream` 与 `ConversationID` 用量关联；网关只实现 `chat` 与 `embedding` 能力。

| 能力 | mygo 0.6.4 结论 | 影响 |
| --- | --- | --- |
| 多行表单 | `TextAreaBase`（007 输入框已用，`Lines(1, 8)`） | 子 Agent 人设编辑 |
| 弹窗 | `ui.Modal` / `mygo.Dialog.Message`（007 §2 已核实） | 新建 / 编辑子 Agent、删除确认 |
| 下拉选择 | `ui.Select`（007 模型下拉已用） | 子 Agent 绑定 `chat` 目标 |
| 列表菜单 | `PopoverBase`（007 行菜单已用） | 子 Agent 行「⋮」菜单 |
| 异步回调 | `mygo.RunOnMain` | 规划、执行、汇总结果回主线程 |
| 重绘 | `Window.Invalidate` | 任务状态变化刷新 |
| 线程安全 | 无内置增量缓冲 | 任务状态只在主线程改写，存储层加锁 |
| 路径 | `platform.AgentDir()` / `platform.TaskDir()`（新增） | 子 Agent 与任务目录 |
| 结构化输出 | 网关无 `response_format` 透传 | 用提示词约束 JSON，不做供应商特性依赖 |

关键结论：界面与调度均可在现有 API 上完成；需要新增的是任务数据层、受限并发执行器、结构化解析与子 Agent 管理界面。

## 3. 设计规格

### 3.1 分层与依赖

```text
internal/task/
  task.go        # 任务组 / 任务结构、状态、校验、上限、ID
  store.go       # 任务目录加载、保存、删除、重启恢复、损坏跳过
  scheduler.go   # 受限并发调度，执行函数由调用方注入
  *_test.go
internal/agent/
  subagent.go    # 子 Agent 结构、校验、存储（JSON）
  dispatch.go    # 规划调用、确认、派发编排、汇总
  page.go        # 左栏 Agent 列表、任务卡片、子 Agent 表单、任务模式开关
  *_test.go
internal/app/agent.go  # 装配任务目录、任务存储、dispatch
```

| 项 | 规格 |
| --- | --- |
| 依赖方向 | `internal/task` 不依赖任何业务包；`internal/agent → internal/task`、`internal/agent → internal/gateway` |
| 调度解耦 | `task.Scheduler` 接收 `func(ctx context.Context, t *Task) Outcome`，不感知网关 |
| 门面 | `task.Store` 管数据；`task.Scheduler` 管并发；`agent.Dispatcher` 组合两者并调用网关 |
| 装配 | `internal/app/agent.go` 新建 `task.NewStore(platform.TaskDir())`，与 `agent.Store` 一起注入 `agent.Page` |
| 线程 | 存储加锁；网络调用在锁外；视图只读快照，不做阻塞 IO |
| 生成互斥 | `Runner` 增加 `ReserveExternal()` / `ReleaseExternal()`；派发期间占用生成位，普通发送与重新生成禁用 |

### 3.2 子 Agent 数据

目录：`{DataDir}/agent/`，文件 `subagents.json`，权限 `0600`，目录 `0700`。

```json
{
  "schema": 1,
  "agents": [
    {
      "id": "a-1a2b3c4d",
      "name": "资料整理",
      "persona": "你负责把用户提供的材料整理成要点清单…",
      "provider_id": "p-1a2b3c4d",
      "model": "gpt-4o-mini",
      "enabled": true,
      "created_at": 1790000000,
      "updated_at": 1790000100
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `schema` | 必须为 `1`；其他版本不加载，记录日志，不删除原文件 |
| `id` | `a-` + 8 位十六进制；主 Agent 固定 `main`，不写入本文件 |
| `name` | 去空白后 1–32 字符，同文件内不区分大小写唯一 |
| `persona` | 去空白后 1–2000 字符，作为子 Agent 的 `system` 消息 |
| `provider_id` / `model` | 必须能在 `gateway.ChatTargets()` 中找到且供应商启用；保存时校验，失效时该 Agent 禁用派发并提示重新配置 |
| `enabled` | 停用后不出现在规划候选，也不可派发；历史任务保留执行者名称快照 |
| 上限 | 最多 20 个；达到上限时「新建」禁用并说明 |
| 落盘 | 临时文件 + `os.Rename` 原子替换；失败保留内存并提示 |
| 损坏 | 整体损坏时记录日志并回退为空列表，不删除原文件；界面提示「子 Agent 配置损坏」 |
| 删除 | 二次确认；有运行中任务时拒绝；历史任务与汇报不删除 |
| 名称快照 | 任务保存 `assignee_name`，子 Agent 改名或删除后卡片仍显示原名 |

### 3.3 任务数据

目录：`{DataDir}/tasks/`，每任务组一个文件 `<gid>.json`，权限 `0600`。

```json
{
  "schema": 1,
  "id": "g-1a2b3c4d",
  "conversation_id": "c-1a2b3c4d",
  "message_index": 3,
  "provider_id": "p-1a2b3c4d",
  "model": "gpt-4o-mini",
  "status": "pending",
  "created_at": 1790000000,
  "updated_at": 1790000100,
  "tasks": [
    {
      "id": "t-1a2b3c4d",
      "goal": "整理会议纪要的待办事项",
      "input": "…",
      "criteria": "输出按负责人分组",
      "assignee_id": "a-1a2b3c4d",
      "assignee_name": "资料整理",
      "status": "pending",
      "report": {
        "conclusion": "…",
        "artifacts": ["待办清单"],
        "open_issues": ["缺少负责人"],
        "summary": "…",
        "unstructured": false
      },
      "input_tokens": 0,
      "output_tokens": 0,
      "usage_estimated": false,
      "duration_ms": 0,
      "error_code": "",
      "error_message": "",
      "retry_of": "",
      "created_at": 1790000000,
      "updated_at": 1790000100
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| 任务组状态 | `pending` 待确认、`running` 执行中、`summarizing` 汇总中、`done` 已完成、`canceled` 已取消、`failed` 已失败、`interrupted` 已中断 |
| 任务状态 | `pending` 待开始、`running` 执行中、`done` 已完成、`failed` 已失败、`canceled` 已取消、`interrupted` 已中断 |
| `message_index` | 卡片所在助手消息的索引；消息被删除后卡片按 `conversation_id` 找不到就不再渲染 |
| 任务组状态推导 | 有待确认 → `pending`；有执行中 / 待开始 → `running`；全部终态且至少一条完成 → `summarizing` → `done`；全部失败或取消 → `failed`；取消 → `canceled`；重启中断 → `interrupted` |
| 终态 | 任务与任务组的 `done` / `failed` / `canceled` / `interrupted` 不再变更；重试生成新任务并写 `retry_of` |
| 上限 | 单计划 1–5 条任务；`goal` 1–200 字符；`input` ≤2000 字符；`criteria` ≤200 字符；单文件 ≤2 MiB |
| 落盘 | 每次状态变化后原子保存整组；流式与逐字内容不落盘 |
| 加载 | JSON 损坏、schema 不符、字段非法或超过 2 MiB 的文件跳过并记录日志，不删除 |
| 重启恢复 | `running` / `summarizing` 的任务组改为 `interrupted`，其中 `pending` / `running` 任务改为 `interrupted`；`pending` 待确认的组保留，可继续确认；`done` / `failed` / `canceled` 不变 |
| 排序 | 任务组按 `updated_at` 倒序；009 任务中心复用该排序 |
| 删除 | 008 不提供任务删除入口；保留策略随数据中心计划 |

`agent.Message` 增加可选字段 `task_group_id`（`omitempty`，只增不改）。带该字段的助手消息不渲染气泡，渲染为任务卡片；`content` 为空时 `buildMessages` 已会跳过，不影响后续上下文。

### 3.4 调度

| 项 | 规格 |
| --- | --- |
| 并发 | 同一任务组内最多 2 条任务同时在途；空闲槽位按任务顺序取 `pending` |
| 互斥 | 一个任务组运行期间其他任务组不可确认；全局只有一条对话生成或一个派发在运行 |
| 超时 | 规划 60s、单任务 120s、汇总 120s；超时按 `timeout` 类错误记入任务 |
| 取消 | 取消任务组取消所有在途 `context`，待开始任务标记 `canceled`；单任务取消只影响该条 |
| 重试 | 仅 `failed` 任务可重试，生成新任务（`retry_of` 指向原任务）并重新排队；原任务记录保留 |
| 中断 | `interrupted` 任务与任务组不提供重试、取消或继续按钮 |
| 事件 | 每次任务状态变化经 `mygo.RunOnMain` 更新并 `Invalidate`，同时立即持久化 |
| 汇总触发 | 所有任务进入终态后进入 `summarizing`，调用一次主 Agent 汇总，成功后 `done` |
| 失败汇总 | 全部任务失败或取消时仍调用一次汇总，要求说明失败原因与影响；汇总失败则组标记 `failed` |
| 空计划 | 规划返回 0 条任务视为解析失败，走重试与回退 |

### 3.5 规划与汇报契约

规划请求：主 Agent 当前 `ProviderID + Model`，`Stream=false`，`MaxTokens=1200`，`Temperature=0.2`；`system` 为主 Agent 人设 + 规划规则，`user` 为当前用户消息 + 可用子 Agent 列表（`id`、`name`、人设首行）。

规划输出：

```json
{"tasks":[{"goal":"…","input":"…","criteria":"…","assignee":"a-1a2b3c4d"}]}
```

规划规则：

- 只输出 JSON，不加解释与代码块。
- 1–5 条任务；`assignee` 必须是候选列表中的 ID，按 ID 精确匹配，不做名称模糊匹配。
- 每条任务自包含；不派发给已停用或不存在的 Agent。
- 无法合理拆解时返回 `{"tasks":[]}`。

解析与回退：

- 先按整体 JSON 解析；失败时尝试剥离 ```json 代码块；再失败则追加一条「上次输出不是合法 JSON，请只输出 JSON」并重试 1 次。
- 两次均失败：不创建任务组，追加一条助手消息说明「无法拆解任务，已按普通回答处理」，并附错误分类 `model`。
- 字段越界、`assignee` 无效、任务数为 0：按解析失败处理，不静默丢弃条目。

汇报请求：子 Agent人设 + 汇报规则为 `system`，目标 / 输入 / 完成标准为 `user`；`Stream=false`，`MaxTokens=1200`，`Temperature=0.2`。

汇报输出：

```json
{"conclusion":"…","artifacts":["…"],"open_issues":["…"],"summary":"…"}
```

| 情形 | 处理 |
| --- | --- |
| JSON 合法且字段类型正确 | 写入 `report`，`unstructured=false` |
| JSON 非法 / 字段类型错误 | 重试 1 次；仍失败则 `conclusion` 取全文（截断 4000 字符），`open_issues` 写「未按结构返回」，`unstructured=true` |
| 空内容 | 任务标记 `failed`，错误分类 `model`，文案「子 Agent 没有返回内容」 |
| 调用失败 | 任务 `failed`，写入网关八类错误分类与面向用户的原因 |

### 3.6 界面

```text
┌────────────────┬───────────────────────────────┬─────────────────────┐
│ 助手            │ 会话标题        收起会话列表     │ 会话          新会话 │
│ [主 Agent]      │                               │ 会话 A           ⋮ │
│ [子 Agent A] ⋮  │  ┌───────────────────────────┐ │ 会话 B           ⋮ │
│ [子 Agent B] ⋮  │  │ 任务计划 3 项   执行  放弃  │ │                     │
│ + 新建子 Agent   │  │ 1 整理… 资料整理  待开始    │ │                     │
│                │  │ 2 汇总… 写作    待开始     │ │                     │
│ 网关状态        │  └───────────────────────────┘ │                     │
│                │  …消息流…                      │                     │
│                │ ┌───────────────────────────┐ │                     │
│                │ │ 输入消息…                  │ │                     │
│                │ │ ⎘ 任务模式(关) [模型▾] (↑)  │ │                     │
│                │ └───────────────────────────┘ │                     │
└────────────────┴───────────────────────────────┴─────────────────────┘
```

| 区域 | 内容 |
| --- | --- |
| 左栏 | 标题「助手」；主 Agent 与子 Agent 使用同一行布局（头像 36、名称、人设两行），选中行主题色底；子 Agent 行右侧「⋮」；底部「+ 新建子 Agent」；不重复展示网关状态（由左侧全局侧栏承载） |
| 选中与直接对话 | 点击主 Agent 或子 Agent 行切换当前 Agent；会话列表与消息流只显示该 Agent 的会话；子 Agent 会话使用其绑定模型与人设作为 `system`，模型选择器显示为只读目标 |
| 子 Agent 行菜单 | 编辑、启用 / 停用、删除；同一时刻只开一个菜单；运行中任务时删除置灰并提示原因 |
| 子 Agent 表单 | `ui.Modal`：名称、人设多行（1–8 行自适应）、模型下拉（`chat` 目标）、启用开关；保存与取消；校验错误显示在字段下方，不关闭弹窗 |
| 任务模式开关 | 输入区工具行，回形针右侧：开启为主题色描边标签「任务模式」，关闭为灰字；状态只存内存；仅在主 Agent 会话可用，切到子 Agent 时自动关闭并禁用 |
| 任务卡片 | 卡片顶部「任务计划 N 项」与状态；任务行含序号、目标（截断两行）、执行者、状态标签、耗时与 token（终态显示） |
| 待确认 | 底部按钮「执行」（主题色）与「放弃」；「执行」后卡片立即转为执行中 |
| 执行中 | 底部「取消全部」；逐条状态实时更新；卡片不遮挡输入区，随消息流滚动 |
| 失败 | 失败任务行显示错误分类与原因，「重试」按钮生成新任务；任务组内其他任务不受影响 |
| 取消 / 中断 / 完成 | 只读展示；完成与失败后紧跟一条汇总助手消息（普通气泡，含模型、耗时、token） |
| 汇总中 | 卡片底部显示「正在汇总…」，期间发送禁用 |
| 空状态 | 无子 Agent 时左栏显示「还没有子 Agent，创建后可派发任务」；任务模式在无启用子 Agent时禁用并提示 |
| 布局 | 960×640 下左栏不横向溢出；任务卡片宽度随中栏，任务目标两行截断 |
| 主题 | 全部走 `internal/ui` 令牌，亮暗主题可读 |

### 3.7 状态与禁用

| 场景 | 行为 |
| --- | --- |
| 网关未配置 / 离线 | 任务模式禁用，提示「网关不可用，无法派发任务」；普通对话沿用 007 规则 |
| `chat` 无目标 | 任务模式禁用，提示「模型未配置」 |
| 无启用子 Agent | 任务模式禁用，提示「先创建并启用子 Agent」 |
| 子 Agent 模型失效 | 该 Agent 行标注「模型不可用」，不进入规划候选；全部失效时任务模式禁用 |
| 正在派发 | 发送、重新生成、任务模式切换禁用；「取消全部」可用 |
| 有待确认任务组 | 允许普通对话，但再次派发需先处理当前计划（执行或放弃） |
| 任务数 / 子 Agent 达上限 | 对应按钮禁用并说明 |

### 3.8 安全与日志

- 任务文件与子 Agent 文件只存配置、目标与汇报，不存密钥、请求头与完整 URL。
- 日志只记录任务组 ID、任务 ID、状态与错误分类；不记录目标、输入、人设与汇报正文。
- 面向用户的错误文案不含宿主绝对路径与密钥。
- 目录与文件权限按 3.2 / 3.3；不进入版本库。
- 子 Agent 与任务目录由 `platform.AgentDir()` / `platform.TaskDir()` 提供，其他包不自行拼接。

## 4. 优先级评估与实施顺序

结论：**先数据契约与存储，再调度，再编排，最后界面与装配**。任务数据结构被调度、编排、界面与 009 同时依赖，必须先定；受限并发与取消是最高风险点，应尽早用替身覆盖。

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | `internal/task` 结构、状态机、校验、原子写、重启恢复 | 所有后续环节依赖 |
| P0 | `Scheduler` 并发、超时、取消、重试 | 最高风险，决定任务组能否收敛 |
| P0 | 子 Agent 结构与存储、`chat` 目标校验 | 规划候选与派发前置 |
| P0 | 规划调用、解析重试、确认、编排、汇总 | 核心价值 |
| P0 | 任务卡片、子 Agent 列表与表单、任务模式开关 | 用户可见主路径 |
| P1 | 用量 `task_id` 透传 | 满足 FR-GW-06 关联要求 |
| P1 | `app` 装配、退出取消、文档回写 | 满足 DoD |
| P1 | 人工验收 | 真实模型结构化输出与视觉无法自动化 |

## 7. 验收标准

- 左栏显示主 Agent 与已创建子 Agent；「+ 新建子 Agent」可打开表单并保存，重启后保留。
- 点击子 Agent 行切换到该 Agent：会话列表只显示它的会话，发送使用其绑定模型与人设；点击主 Agent 行恢复主会话。左栏不重复展示网关状态。
- 子 Agent 名称重复、人设为空、模型不在 `chat` 路由时保存被拒绝并显示原因。
- 停用子 Agent 后不再出现在规划候选；删除有运行中任务的子 Agent 被拒绝；删除后历史任务仍显示原执行者名称。
- 任务模式关闭时发送行为与 007 完全一致，不触发规划调用。
- 任务模式开启发送后出现「任务计划 N 项」卡片，列出目标、执行者与状态；点「放弃」不发起任何模型调用。
- 点「执行」后最多 2 条任务同时在途，状态逐条更新；完成后出现汇总助手消息，含模型、耗时与 token。
- 规划返回非法 JSON 时自动重试 1 次；仍失败则显示「无法拆解任务」且不创建任务组。
- 子 Agent 汇报非法 JSON 时按纯文本结论收录，卡片显示「未按结构返回」。
- 单条任务失败显示错误分类与原因，可重试生成新任务；原任务与汇报保留。
- 「取消全部」立即停止在途请求，未开始任务标记已取消，任务组标记已取消。
- 退出并重启后，执行中的任务组与任务显示「已中断」，且没有继续 / 重试按钮；其他状态不受影响。
- 损坏的任务文件与子 Agent 文件被跳过，不删除，不影响其他记录。
- `usage.jsonl` 中派发相关调用带 `origin=agent`、`conversation_id` 与 `task_id`，无目标与汇报正文。
- 960×640 与亮 / 暗主题下卡片、表单、左栏不横向溢出；派发期间界面可滚动、可切换模块。
- `gofmt -l .` 无输出，`go vet ./...`、`go test ./...` 通过，`go tool mygo build` 成功。

## 11. 人工验收步骤

验收入口：`go tool mygo build` 后运行 `build/windows-amd64/Bowknot Agent.exe`，或开发时 `go tool mygo dev`。子 Agent 与任务文件分别位于 `C:/Users/<用户>/.bowknot-agent/agent/subagents.json` 与 `C:/Users/<用户>/.bowknot-agent/tasks/`。

1. 子 Agent 管理
   - 操作：进入「助手 / Agent」，点左栏「+ 新建子 Agent」，填名称「资料整理」、人设「把材料整理成要点清单」、选择模型并保存；再用同名新建一次。
   - 预期：保存后左栏出现该行与「⋮」；重名保存被拒绝并显示原因；重启后仍在。
   - 重点：表单不遮挡输入区，校验错误显示在字段下方。

2. 启用 / 停用 / 删除
   - 操作：通过「⋮」停用，再重新启用；删除时取消一次、确认一次。
   - 预期：停用后规划候选不再包含该 Agent；取消删除列表不变，确认后移除；历史任务卡片仍显示其名称。
   - 重点：有运行中任务时删除被拒绝并说明原因。

3. 任务模式关闭
   - 操作：保持任务模式关闭，发送「你好」。
   - 预期：与 007 行为一致，逐字流式回复，无任务卡片、无规划调用。
   - 重点：`usage.jsonl` 中该次调用没有 `task_id`。

4. 规划与确认
   - 操作：开启「任务模式」，发送一个可拆分的目标（如「帮我整理下面三段材料并分别给出要点」）。
   - 预期：出现「任务计划 N 项」卡片，列出目标与执行者；不点执行时无子 Agent调用。
   - 重点：卡片不超出中栏宽度，任务目标两行截断。

5. 执行与汇总
   - 操作：点「执行」。
   - 预期：最多两条任务同时执行中；状态逐条变为已完成；结束后出现汇总助手消息，含模型、耗时与 token。
   - 重点：执行中界面仍可滚动、可切换模块；发送按钮禁用。

6. 放弃与取消
   - 操作：对一张待确认卡片点「放弃」；再对一张执行中卡片点「取消全部」。
   - 预期：放弃不发请求、卡片标记已取消；取消后状态立即变为已取消，无迟到更新。
   - 重点：取消后普通发送恢复可用。

7. 失败与重试
   - 操作：把某个子 Agent 指向错误地址或在调用中改错密钥后执行，再恢复配置点该任务的「重试」。
   - 预期：失败任务显示错误分类与原因；重试生成新任务并重新排队；原失败任务记录保留。
   - 重点：错误文案不含密钥与绝对路径。

8. 结构化失败回退
   - 操作：使用一个倾向于输出解释性文字的模型触发规划与汇报。
   - 预期：规划失败时提示「无法拆解任务」且不创建任务组；汇报失败时按纯文本结论收录并标注「未按结构返回」。
   - 重点：界面不出现空白卡片或卡死。

9. 重启恢复
   - 操作：执行一个较长任务组，执行中直接退出应用并重启。
   - 预期：任务组与在途任务显示「已中断」，无继续 / 重试按钮；已完成与已取消的组不受影响。
   - 重点：启动无卡顿，卡片位置与消息顺序保持。

10. 持久化与损坏
    - 操作：把一个任务 JSON 改坏，再重启。
    - 预期：该组被跳过，其他组正常，原文件未被删除。
    - 重点：无控制台报错轰炸。

11. 用量与隐私
    - 操作：完成一次派发后查看 `~/.bowknot-agent/gateway/usage.jsonl`。
    - 预期：规划、子 Agent、汇总调用均记录 `origin=agent`、`conversation_id`，子 Agent 与汇总调用带 `task_id`；无目标、输入与汇报正文。
    - 重点：日志文件同样不含正文。

12. 主题与最小窗口
    - 操作：切换到暗色主题，把窗口缩到 960×640，滚动含多张任务卡片的会话。
    - 预期：左栏、卡片、状态标签可读，无横向溢出；输入区固定底部。
    - 重点：暗色下失败文案与「执行」按钮对比度。

13. 直接与子 Agent 对话
    - 操作：在左栏点击某子 Agent 行，发送一条消息；再点回主 Agent 行。
    - 预期：选中行高亮；右栏只显示该 Agent 的会话，回复使用其绑定模型与人设，模型选择器为只读目标；切回主 Agent 恢复主会话；任务模式在子 Agent 会话下禁用。
    - 重点：切换后消息不串会话；主 Agent 与子 Agent 行布局一致；左栏底部不再出现网关状态。
