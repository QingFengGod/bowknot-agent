## 1. 简介

在 007 对话能力之上做多 Agent 与任务派发最小闭环：子 Agent 完整 CRUD、任务模式开关、主 Agent 结构化拆解 + 用户确认、受限并发执行、结构化汇报与主 Agent 汇总、任务本地持久化与重启标记「已中断」。不做子 Agent 协作、工具调用、审批、记忆、任务中心与任务嵌套。

> 需求 v0.2 起，本计划的「助手 / Agent 单模块、子 Agent 列表、任务模式」由 010、011 替代，任务派发与任务中心由 014–016 替代。

## 3. 实施顺序

`T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8 → T9 → T10 → T11 → T12 → T13 → T14`

任务数据契约与状态机被调度、编排、界面同时依赖，先定（T1–T3）；受限并发与取消是最高风险，紧接着用替身覆盖（T4）；子 Agent 数据与 `task_id` 透传完成后，编排（T7、T8）才有输入；最后做界面与装配；验收反馈修复追加在末尾（T14）。
