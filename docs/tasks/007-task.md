## 1. 目标

### 1.1 本次交付

1. `internal/agent` 核心：主 Agent 单例、会话模型、会话存储（每会话一个 JSON，原子落盘）。
2. 对话执行器：消费 006 的 `gateway.Service.Chat` 流式能力，增量回调回主线程，支持中止、失败保留、重新生成。
3. 三栏助手页：左栏主 Agent 列表、中栏消息流、右栏会话列表（可收起）。
4. 状态联动：网关未配置 / 离线 / 无 `chat` 目标时禁用输入并说明原因。
5. 用量关联：`origin=agent`，`UsageRecord` 增加可选 `conversation_id`（只增不改）。
6. `internal/app` 装配助手模块，替换占位卡片。
7. 单元测试、自检与人工验收步骤。

### 1.2 非目标

- 不做子 Agent 创建、编辑、停用、删除（FR-AGT-02）。
- 不做任务派发、汇报、协作与协作视图（FR-AGT-04 / 05 / 06 / 11 / 12）。
- 不做任务中心、任务状态机与重启恢复「已中断」（FR-TASK-01–03）。
- 不做高风险审批（FR-AGT-08）与运行追踪断点重试（FR-AGT-09）。
- 不做长期记忆、记忆引用与检索（FR-MEM）。
- 不做工具调用、插件、图片 / 视频 / 语音生成。
- 不做人设编辑、Agent 头像选择与多 Agent 列表。
- 不做全局唤起、通知、命令面板与桌宠联动。
- 不做流式费用的实时估算；token 仍以供应商返回为准。
- 不做 macOS 实机验收，Windows 先验收。

## 2. 前置状态与 mygo API 核实

`internal/agent` 目前为空目录，助手模块在壳中显示「内容将在后续计划中实现」。006 已提供：`Service.Chat`（含流式与路由回退）、状态快照、错误分类、JSONL 用量。设置页已建立 `internal/settings/page.go` 的视图与测试范式，可复用。

| 能力 | mygo 0.6.4 结论 | 影响 |
| --- | --- | --- |
| 文本输入 | `ui.TextInput(c, *string)`，`Element.Password()` | 输入框与提示词 |
| 列表 / 滚动 | `ui.Column` + `Scroll` 容器 | 会话列表、消息流 |
| 弹窗确认 | `mygo.Dialog.Message` 或 `ui.Modal` | 删除会话二次确认 |
| 异步回调 | `mygo.RunOnMain(func())` | 流式增量与网络结果回主线程 |
| 重绘 | `Window.Invalidate()` | 每次增量刷新 |
| 线程安全 | 无内置增量缓冲 | 需自行节流，见 3.4 |
| 路径 | `platform.DataDir()` | 新增 `AgentDir()` |
| 流式 | 无专用 UI API | 复用 006 的 `ChatRequest.OnDelta` |

关键结论：三栏布局、流式增量与中止均可在现有 API 上完成；需要新增的是会话数据层、增量节流与一次性生成控制。

## 3. 设计规格

### 3.1 分层与依赖

```text
internal/agent/
  agent.go       # 主 Agent 单例、默认人设、只读展示模型
  conversation.go# 会话与消息结构、校验、标题生成、schema
  store.go       # 会话目录加载、创建、保存、删除、排序、损坏回退
  runner.go      # 对话执行、流式缓冲、中止、重新生成、用量关联
  page.go        # 三栏视图、输入、消息流、会话面板、空状态
  *_test.go
internal/app/agent.go   # 装配：目录、网关注入、页面注入、退出收尾
```

| 项 | 规格 |
| --- | --- |
| 依赖方向 | `internal/agent → internal/gateway`；核心不依赖 `ui` / `shell` / `app`；`page.go` 依赖 `internal/ui` 与 mygo |
| 门面 | `agent.Store` 负责数据；`agent.Runner` 负责调用；`agent.Page` 组合两者 |
| 网关接口 | 页面与执行器依赖窄接口 `Chatter`，测试注入替身，不发真实请求 |
| 装配 | `app` 新建 `internal/app/agent.go`，把 `Page` 注入 `shell.Pages[ModuleAgent]` |
| 线程 | 会话存储加锁；网络与流式在锁外；视图只读内存快照，不做阻塞 IO |
| 状态 | 页面通过 `func() gateway.Snapshot` 读取实时状态；不缓存业务状态到 shell |

窄接口：

```go
// Chatter is the part of the gateway the assistant uses.
type Chatter interface {
    Chat(ctx context.Context, req gateway.ChatRequest, origin string) (gateway.ChatResponse, error)
    Snapshot() gateway.Snapshot
}
```

### 3.2 主 Agent

| 项 | 规格 |
| --- | --- |
| 数量 | 唯一，固定 ID `main`，不可删除 |
| 默认名称 | `Bowknot 助手` |
| 人设 | 常量文本（中文、简洁、明确说明无法执行工具与访问文件），作为 `system` 消息随每次请求发送 |
| 头像 | 沿用 `ui.AgentIcon` 占位，不做上传 |
| 模型 | 只读展示 `gateway.Snapshot().Model`；为空显示「模型未配置」 |
| 编辑 | 本期不提供；人设变更留到 Agent 管理计划 |

### 3.3 会话数据

目录：`{DataDir}/agent/`，目录权限 `0700`；会话文件 `conversations/<id>.json`，文件权限 `0600`。

```json
{
  "schema": 1,
  "id": "c-1a2b3c4d",
  "title": "帮我总结这段文字",
  "created_at": 1790000000,
  "updated_at": 1790000100,
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "user", "content": "…", "at": 1790000000},
    {
      "role": "assistant",
      "content": "…",
      "model": "gpt-4o-mini",
      "input_tokens": 12,
      "output_tokens": 34,
      "usage_estimated": false,
      "duration_ms": 1200,
      "status": "ok",
      "at": 1790000100
    }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `schema` | 必须为 `1`；其他版本跳过加载并记录日志，不删除文件 |
| `id` | `c-` + 8 位十六进制，内部生成 |
| `title` | 首条用户消息去空白、折叠换行后取前 30 个字符；为空时「新会话」 |
| `title_edited` | 用户手动重命名后为 `true`，此后首条用户消息不再覆盖标题；`omitempty`，旧文件缺失按 `false` 处理 |
| `created_at` / `updated_at` | Unix 秒；每次追加消息更新 `updated_at` |
| `model` | 会话最近一次成功调用的实际模型；未知为空 |
| 消息 `role` | `user` / `assistant` |
| 消息 `status` | `ok` / `error` / `aborted`；用户消息固定 `ok` |
| 错误字段 | 助手消息可用 `error_code`（八类）与 `error_message`（面向用户，不含路径与密钥） |
| 上限 | 单会话最多 500 条消息；达到上限后输入区提示「新建会话后继续」并禁用发送 |
| 落盘 | 临时文件 + `os.Rename` 原子替换；失败返回错误，内存保留本次内容并提示 |
| 损坏 | JSON 损坏、字段非法或超过 4 MiB 的文件跳过加载，日志记录，不删除原文件 |
| 排序 | 会话列表按 `updated_at` 倒序 |
| 删除 | 二次确认后删除文件；不可恢复，不做回收站 |

会话操作本期：新建、切换、重命名（行内编辑）、删除；重命名只改 `title`，不改变 `updated_at`。

### 3.4 对话执行

| 项 | 规格 |
| --- | --- |
| 请求 | `ChatRequest{Messages: system + 会话消息, Stream: true, OnDelta}`；不设 `MaxTokens` 与 `Temperature` |
| 流式 | `OnDelta` 在读取 goroutine 内触发；按 50ms 节流合并后经 `mygo.RunOnMain` 更新当前助手消息并 `Invalidate` |
| 并发 | 全局最多一个生成；生成期间「发送」禁用，「停止」可用；切换会话不中止，生成结果写回其所属会话 |
| 中止 | 用户点「停止」或退出应用时取消 `context`；已生成内容保留，`status=aborted`，可在该条上「重新生成」 |
| 失败 | 保留已生成内容，`status=error`，显示分类与原因；`moderation` 与 `internal` 不回退由网关保证 |
| 重新生成 | 仅对最后一条助手消息可用：丢弃该消息，重发其之前的全部消息，新回复替换该位置 |
| 用量 | 成功后写一条 `origin=agent`、`conversation_id=<会话 ID>` 的记录；失败与中止沿用网关现有记录规则 |
| 持久化时机 | 用户消息发送前保存一次；回复完成、中止或失败后保存一次；流式过程不逐字落盘 |
| 退出 | `OnBeforeQuit` 先取消进行中的生成并保存，再关闭窗口 |
| 空回复 | 供应商返回空内容视为 `model` 类错误，提示「模型没有返回内容」 |

消息展示：

- 用户消息右对齐、强调底色；助手消息左对齐、表面色。
- 助手消息底部显示实际模型、耗时与「输入 X · 输出 Y token」；未返回用量显示「token 用量未返回」。
- 失败与中止消息下方显示分类文案与「重新生成」。
- 生成中显示流式光标；停止后光标消失。

### 3.5 状态与禁用

| 场景 | 行为 |
| --- | --- |
| 网关未配置 | 三栏可查看，输入禁用，提示「网关未配置，配置后可启用对话」 |
| 网关离线 | 输入禁用，提示「网关离线，恢复连接后可启用对话」；已有会话仍可查看 |
| `chat` 无目标 | 输入禁用，提示「模型未配置，请先在设置中配置对话模型」 |
| 正在生成 | 发送禁用、停止可用；输入框可编辑，停止后可直接发送 |
| 超过 500 条 | 发送禁用，提示新建会话 |

状态来源为 `gateway.Snapshot()`；快照变化由 `app` 现有的 `SetOnSnapshot` 触发 `Invalidate`，页面不额外订阅。

### 3.6 三栏界面

```text
┌────────────────┬───────────────────────────────┬─────────────────────┐
│ 助手            │ 会话标题        收起会话列表     │ 会话          新会话 │
│ [头像] 主 Agent │ 消息流（可滚动、跟随末尾）      │ 会话 A           ⋮ │
│                │ [↓ 回到底部]（上翻时出现）      │ 会话 B           ⋮ │
│                │ ┌───────────────────────────┐ │                     │
│ 网关状态        │ │ 输入消息…（1–8 行自适应）   │ │                     │
│                │ │ ⎘  提示文案  [模型 ▾]  (↑) │ │                     │
│                │ └───────────────────────────┘ │                     │
└────────────────┴───────────────────────────────┴─────────────────────┘
```

| 区域 | 内容 |
| --- | --- |
| 左栏（300） | 「助手」标题；主 Agent 行（头像、名称、人设两行，无菜单按钮）；底部网关状态点与文案 |
| 中栏（弹性） | 会话标题与右侧的会话列表开关（右栏显示时为「收起会话列表」，收起时为「打开会话列表」）；消息流；上翻时出现「↓ 回到底部」；输入区为 `ui.ComposerView` 组件：大圆角容器内 1–8 行自适应输入，底部工具行为附件图标、提示文案、模型下拉与圆形发送 / 停止图标按钮 |
| 右栏（280，可收起） | 标题行「会话」+ 主题色文字「新会话」；会话行（标题、消息数、右侧「⋮」，选中高亮，最多最近 20 条）；无会话时显示「还没有会话」 |
| 行菜单 | 「⋮」用 `PopoverBase` 渲染在窗口覆盖层，随锚点滚动，点击外部或 Escape 关闭；同一时刻只开一个菜单；菜单项为重命名会话、删除会话 |
| 面板收起 | `ConvPanelHidden` 控制；右栏整体不渲染，不做过渡动画（当前渲染下 `Transition` 会先跳变再播一遍残影）；新建会话会自动展开 |
| 空状态 | 无会话时中栏显示「开始一段新对话」；有会话无消息时显示提示语 |
| 布局 | 960×640 最小窗口下三栏不横向溢出；消息流与会话列表各自滚动，输入区固定底部 |
| 主题 | 全部走 `internal/ui` 令牌，亮暗主题可读 |
| 滚动 | 消息流用 `TrackScroll` 跟随末尾；上翻超过 24 阈值时显示「↓ 回到底部」，点击平滑滚到末尾 |
| 输入 | `TextAreaBase.Lines(1, 8)` 多行自适应；Enter 发送（`OnTextKey`），Shift+Enter 换行；发送后清空草稿 |
| 发送 / 停止 | 单一圆形按钮：空闲为主题色（`t.Accent`）发送箭头图标，生成中变为停止方块图标；草稿为空或网关阻断时禁用置灰 |
| 附件 | 工具行左侧回形针图标（28×28），本期仅预留槽位，`OnAttach` 为 nil 时置灰不可点 |
| 模型 | 工具行右侧、发送按钮左侧的下拉，列出 `chat` 路由目标；选择后本次及后续请求固定该目标（`ChatRequest.ProviderID` + `Model`），不做回退 |
| 异步 | 视图函数不做网络 IO；流式增量与结果均经 `RunOnMain` |

运行详情右栏自 2026-10-28 起不再展示：模型、耗时与 token 已在其消息气泡内展示，错误与中止状态也在气泡下方标注。

### 3.7 用量关联

`gateway.UsageRecord` 增加可选字段：

```go
ConversationID string `json:"conversation_id,omitempty"`
```

`gateway.ChatRequest` 增加 `ConversationID string`，`Service.Chat` / `ChatProvider` 写入记录时透传。旧记录无该字段仍可读取；006 的设置页测试不填，保持为空。`origin` 本期取 `agent`。

### 3.8 安全与日志

- 会话文件只存消息正文与元信息，不存密钥、请求头与完整 URL。
- 日志只记录会话 ID、消息数、状态与错误分类；不记录消息正文。
- 错误文案面向用户，不含宿主绝对路径。
- 会话目录与文件权限按 3.3；不进入版本库。

## 4. 优先级评估与实施顺序

结论：**先数据与执行器，再页面，最后装配与收尾**。会话契约先定，页面与测试都依赖；执行器的流式与中止是本期最高风险点，应尽早用替身覆盖。

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | 会话结构、存储、标题、原子写、损坏回退 | 所有界面与执行器依赖 |
| P0 | `Chatter` 窄接口与流式执行、中止、重新生成 | 核心价值与最高风险 |
| P0 | 三栏页面、空状态、离线禁用、发送 / 停止 | 用户可见主路径 |
| P0 | 会话面板与错误展示 | 无任务中心时的可观测性 |
| P1 | 用量 `conversation_id` 透传 | 满足 FR-GW-06 关联要求 |
| P1 | `app` 装配、退出收尾、文档回写 | 满足 DoD |
| P1 | 人工验收 | 真实流式与视觉无法自动化 |

## 7. 验收标准

- 首次进入助手模块：左栏显示主 Agent 与网关状态；中栏「开始一段新对话」；右栏显示会话面板与「+ 新会话」。
- 网关未配置或离线时输入禁用且原因准确；恢复在线后无需重启即可发送。
- 新建会话 → 发送「你好」→ 回复逐字流式出现；停止后已生成内容保留并显示「已中止」。
- 失败（如错误密钥）时显示错误分类与原因，已生成内容不丢失；「重新生成」替换该条回复。
- 多轮对话上下文正确；切换会话后各自消息不串；列表按最近更新时间倒序。
- 重启应用后会话、消息与标题保留；损坏文件被跳过且不影响其他会话。
- 删除会话需二次确认，确认后文件消失且列表更新；删除最后一个会话回到空状态。
- 单会话达到 500 条后发送禁用并提示新建会话。
- 回复气泡显示模型、耗时与 token；未返回用量显示「token 用量未返回」。
- 右栏可收起 / 展开；收起后不占宽度，中栏提供「会话列表」入口。
- `{DataDir}/agent/conversations/*.json` 中无密钥与绝对路径；日志无消息正文。
- `usage.jsonl` 中助手调用记录 `origin=agent` 且含 `conversation_id`。
- 960×640 最小窗口与亮 / 暗主题下三栏可读、无横向溢出；流式期间界面可滚动、可切换模块。
- `gofmt -l .` 无输出，`go vet ./...`、`go test ./...` 通过，`go tool mygo build` 成功。

## 8. 风险与待确认

| 编号 | 事项 | 影响 | 当前处理 |
| --- | --- | --- | --- |
| R-01 | 真实供应商的 SSE 分片格式存在差异 | 流式可能出现空白或截断 | 006 仅单测覆盖，007 做真实流式人工验收；异常时按行容错 |
| R-02 | 每增量重绘可能造成长回复卡顿 | 输入与滚动不流畅 | 50ms 节流合并；仍卡顿则改为 100ms |
| R-03 | 会话文件无总量上限 | 磁盘占用随使用增长 | 单会话 500 条上限；总量与清理策略随数据中心计划 |
| R-04 | 全局仅一个生成 | 无法并行处理多个会话 | 本期接受；并行度随任务中心评估 |
| R-05 | 网关在线状态依赖最近测试或调用 | 未测试时输入被禁用，即使供应商可用 | 沿用 006 文案，引导先测试；后续可改为探测 |
| R-06 | mygo 输入框回车与滚动 API 未核实 | Enter 发送、自动滚底可能不可用 | 以按钮为主；不具备则只做按钮与手动滚动 |
| R-07 | 崩溃时流式中的内容未落盘 | 当前一轮丢失 | 仅在完成 / 中止 / 退出时保存；本期接受 |
| R-08 | 流式响应常不返回 token 用量 | 消息气泡显示「未返回」 | 标记估算，不做推断（对齐 006） |
| R-09 | 无工具调用与记忆 | 回答能力受模型本身限制 | 人设中明确说明；后续计划补齐 |
| R-10 | macOS 未实机验证 | 输入与滚动行为未知 | Windows 先验收，macOS 列入人工验证 |
| R-11 | 会话 ID 透传改动网关结构 | 影响 006 已验收代码 | 仅新增可选字段，旧记录与设置页测试不变；补回归单测 |

## 11. 人工验收步骤

验收入口：`go tool mygo build` 后运行 `build/windows-amd64/Bowknot Agent.exe`，或开发时 `go tool mygo dev`。会话文件位于 `C:/Users/<用户>/.bowknot-agent/agent/conversations/`。

1. 空状态与入口
   - 操作：启动并进入左侧「助手 / Agent」。
   - 预期：左栏显示主 Agent 头像、名称、人设摘要与底部网关状态，Agent 行没有菜单按钮；中栏标题右侧是「收起会话列表」，显示「开始一段新对话」与模型下拉；右栏标题行是「会话」与主题色「新会话」，列表为「还没有会话」。
   - 重点：三栏无横向溢出，无控制台报错。

2. 离线禁用
   - 操作：在网关未配置或测试失败状态下进入助手。
   - 预期：输入框与圆形发送按钮禁用（按钮置灰、图标为发送箭头），提示文案与侧栏状态一致；可查看已有会话。
   - 重点：离线时不发任何网络请求。

3. 首次流式对话
   - 操作：点「新会话」，在输入框输入「你好」，按 Enter（不带 Shift）发送。
   - 预期：草稿清空；用户气泡出现；助手气泡逐字增长；完成后显示模型、耗时与 token；会话标题由首条消息生成。
   - 重点：流式期间圆形按钮变为停止图标；界面仍可滚动与切换模块。

4. 停止
   - 操作：发送较长问题，在输出中途点圆形停止按钮。
   - 预期：立即停止增长，内容保留，标记「已中止」并出现「重新生成」。
   - 重点：停止后无迟到增量继续写入。

5. 失败与重新生成
   - 操作：临时改错密钥或指向不可用地址后发送；随后恢复配置点「重新生成」。
   - 预期：失败消息显示分类（鉴权 / 网络 / 超时等）与原因，已生成内容保留；恢复后重新生成替换该条回复。
   - 重点：错误文案不含密钥与绝对路径。

6. 多会话与切换
   - 操作：再建一个会话并发消息；在两个会话间来回切换。
   - 预期：消息各自独立，列表按最近更新时间倒序；切换不打断正在进行的生成，回复写回原会话。
   - 重点：快速切换无错位或重复消息。

7. 持久化与损坏回退
   - 操作：退出并重启应用；再把一个会话 JSON 改坏后重启。
   - 预期：正常会话与标题保留；损坏文件被跳过，其他会话可用，原文件未被删除。
   - 重点：启动无明显卡顿。

8. 删除与上限
   - 操作：删除会话（确认弹窗）；以及在一个会话中持续累积到 500 条。
   - 预期：取消删除不改变列表，确认后文件消失；达到 500 条后发送禁用并提示新建会话。
   - 重点：删除确认文案明确不可恢复。

9. 消息用量与用量记录
   - 操作：完成几轮对话后查看助手气泡底部与 `~/.bowknot-agent/gateway/usage.jsonl`。
   - 预期：每条回复气泡显示模型、耗时与 token；不再有「运行详情」右栏；用量记录 `origin=agent` 且含 `conversation_id`，无提示词与回复正文。
   - 重点：未返回用量时显示「token 用量未返回」，不虚构数字。

10. 主题与最小窗口
    - 操作：切换亮 / 暗主题；窗口缩到 960×640，滚动消息流与右栏会话列表；再点中栏标题右侧「收起会话列表」。
    - 预期：三栏文字与边框可读；输入区固定在底部；点击后右栏立即收起、中栏变宽，按钮文案变成「打开会话列表」，再点恢复右栏且无残影。
    - 重点：切换瞬间无闪烁、无双次收放；暗色下错误文案与圆形发送 / 停止按钮对比度。

11. 会话管理
    - 操作：点右栏「新会话」新建；点某会话行「⋮」，选择「重命名会话」并保存，再选「删除会话」。
    - 预期：「新会话」为强调主题色，立即新增并选中；菜单在该行下方展开，点空白处或 Escape 关闭；重命名行内编辑并落盘，重启后保留；删除走中栏二次确认。菜单里不再有「重新生成」，重新生成仍在助手气泡下方按钮上可用。
    - 重点：菜单不被栏位裁剪、不遮挡输入区且滚动列表时跟随按钮；同一时刻只有一个菜单打开。

12. 输入框组件
    - 操作：在输入框输入多行内容（Shift+Enter 换行），观察输入区高度；清空后按 Enter；再点左上回形针图标与右侧模型下拉。
    - 预期：输入区随行数从 1 行增长、最多 8 行后内部滚动；圆角容器与主题色圆形发送按钮符合亮 / 暗主题；空草稿时发送按钮置灰；回形针图标置灰不可点（附件功能未开放）；模型下拉展开并切换后，新请求使用所选目标。
    - 重点：Enter 发送、Shift+Enter 只换行不发送；输入区增高时消息流仍跟随末尾且不遮挡标题行；无闪烁与错位。
