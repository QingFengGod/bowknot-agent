## 1. 目标

### 1.1 本次交付

1. 左侧导航栏底部常驻全局状态：网关状态点与文案、当前模型、用量入口；内容右下对齐，顶部 1px 分隔线。
2. 全局状态快照由 `app` 注入 `shell`；本次固定为「未配置」，但完整定义未配置 / 在线 / 离线三态及文案。
3. 助手与创作占位区在网关不可用时显示禁用原因；网关在线后自动不再显示。
4. `internal/store`：应用条目、8 条内置示例目录、分类、搜索与选中逻辑，全部为本地静态数据。
5. App Store 页面：搜索框、分类筛选、应用列表、详情面板、空结果与清除筛选。
6. 模块状态保留：`Page` 由 `app` 持有一个实例并注入 `shell`，切换模块保留搜索词、分类与选中项。
7. 已安装应用启动器：应用模块默认「已安装」，网格卡片、搜索、状态筛选、排序、空状态与完整状态矩阵。
8. 本地应用注册表：从 `{DataDir}/apps/registry.json` 读取已安装应用；缺文件为空启动器，损坏时记录错误并继续运行。
9. 文档回写：requirements §5.1、FR-SHELL-01、FR-GW-07 的「顶部」改为「左侧导航栏底部」。
10. 单元测试、自检与本计划状态更新。

### 1.2 非目标

- 不做真实网关、供应商配置、连接测试、模型配置。
- 不做用量面板与用量记录；用量入口为禁用占位。
- 不做应用安装 / 卸载 / 启动 / webview / 能力注入。
- 不做注册表写入与目录扫描；启动器只读，安装流程留给后续计划。
- 不做应用图标加载，仍用名称首字母块。
- 不做「最近使用」的实时更新；`LastOpened` 目前只从注册表读取。
- 不做远程商店源、更新检查、真实应用图标、正式应用清单格式。
- 不保留滚动位置，只保留搜索、分类、筛选、排序与选中项；重启后状态重置。
- 不做后台任务与通知。
- 不做 macOS 实机验证，Windows 先验收。

## 2. 前置状态与 mygo API 核实

003 已交付托盘、单实例、关闭到托盘、三态主题、失焦态与平台分支。`internal/gateway` 尚无实现；`internal/store` 在本计划中从空目录扩展为商店与启动器模块。

| 能力 | mygo 0.6.4 结论 | 影响 |
| --- | --- | --- |
| 视图状态 | 立即模式 UI，视图每次重建都从结构体字段读取 | 页面状态必须放在长生命周期对象上，不能放在视图闭包内 |
| 测试 | `mygoui.NewTester(view, width, height)`，`Click` / `Type` / `HasText` / `Frame` / `Image` 可无窗口运行 | 搜索、筛选、选中、状态保留均可自动化验证 |
| 输入框 | `TextInput(ctx, *string)` 绑定指针，输入即写回 | 搜索词可直接存在 `store.Page` |
| 滚动 | `Scroll` 提供滚动容器，未暴露滚动偏移读取与恢复 | 不承诺滚动位置保留，记入 R-02 |
| 按钮 | `ButtonBase` 支持 `Label`、`Disabled`、`Clicked`、悬停 / 按下态 | 分类、应用行、清除筛选、用量入口 |
| 图标 | `Icon` 与既有图标集可直接使用 | 侧栏导航与占位卡片保持 003 的外观 |
| 布局 | `Column` / `Row` / `Spacer` / `Box.Center()` / `AlignItems(End)` | 侧栏底部右下角对齐 |
| 主题令牌 | `Theme.Accent` / `Text` / `TextMuted` / `Surface` / `Border` / `Radius` | 不新增硬编码颜色，只补状态色 |

关键结论：mygo 没有可恢复的滚动偏移 API，因此 004 的状态保留以逻辑状态为界；若后续需要滚动位置，必须先验证隐藏挂载或补充 API，不能在本计划中承诺。

## 3. 设计规格

### 3.1 侧栏底部状态位

| 项 | 规格 |
| --- | --- |
| 位置 | 左侧 220 宽导航栏底部，`Spacer` 之后；内容右对齐，顶部 1px 分隔线 |
| 网关 | 8×8 圆点 + 文案：灰「网关未配置」/ 绿「网关在线」/ 红「网关离线」 |
| 模型 | 快照为空显示「模型未配置」，否则显示模型名 |
| 用量 | 网关在线时可点击；否则 `Disabled`，并显示「用量将随网关接入开放」 |
| 状态源 | `shell.Status{Gateway, Model}`，由 `app` 注入；004 固定 `GatewayNotConfigured` |
| 重绘 | 状态变化后由调用方 `Window.Invalidate()`；004 状态静态，不涉及订阅 |

### 3.2 App Store 数据与筛选

| 项 | 规格 |
| --- | --- |
| 条目字段 | ID、名称、版本、体积、来源、分类、简介、更新说明、安装状态 |
| 目录 | 8 条内置示例，覆盖效率 / 创作 / 开发三类；来源统一「内置示例」 |
| 分类 | 全部 / 效率 / 创作 / 开发，第一项显示所有应用 |
| 搜索 | 去首尾空格、忽略大小写，匹配名称或简介 |
| 筛选顺序 | 先分类后搜索，返回稳定顺序（目录顺序） |
| 选中 | 选中项不在结果中时回退到第一条；结果为空时清空选中 |
| 空状态 | 显示「未找到匹配应用」与「清除筛选」 |

### 3.3 App Store 页面

| 区域 | 内容 |
| --- | --- |
| 页头 | 标题「App Store」、副标题「浏览与安装 WebApp」 |
| 工具栏 | 搜索框（可访问性标签「搜索应用」）、四个分类按钮、结果计数 |
| 列表 | 滚动容器；每行图标字母块、名称、简介、安装状态；选中行橙色背景 |
| 详情 | 320 宽固定面板：字母图标、名称、版本与体积、来源与分类、简介、更新说明、安装状态与后续说明 |
| 布局 | 侧栏 220 + 内容内边距 32×2 + 详情 320 + 间距 16；最小 960 宽时列表仍有约 340 可用 |
| 非目标 | 安装按钮不提供，详情明确写「安装与启动将在后续计划接入」 |

### 3.4 模块状态保留

| 项 | 规格 |
| --- | --- |
| 页面契约 | `shell.Page` 暴露 `View() func(c *mygoui.Context)`，由 `app` 实现并注入 `shell.Pages` |
| 生命周期 | `app.New` 创建一次 `store.Page`，进程内不重建 |
| 保留内容 | 商店的搜索词、分类、选中应用；启动器的搜索词、状态筛选、排序；切走再切回保持不变 |
| 不保留 | 滚动位置、输入光标位置、重启后的状态 |
| 回退 | 未注入页面的模块继续显示 003 的占位卡片 |

### 3.5 已安装启动器与本地注册表

| 项 | 规格 |
| --- | --- |
| 模块结构 | 标题「应用」；「已安装 / 发现」双标签；默认 `TabInstalled` |
| 启动器工具栏 | 搜索「搜索已安装应用」、状态筛选、排序（最近使用 / 名称）、结果计数 |
| 启动器卡片 | 3 列网格；图标字母块、名称、`v版本 · 来源`、简介、状态、主操作 |
| 搜索与筛选 | 去首尾空格、忽略大小写；「全部」为空筛选；「已安装」组含已安装、运行中、可更新、更新中 |
| 排序 | 最近使用：`LastOpened` 降序，未打开过按名称；名称：名称升序 |
| 空状态 | 无注册表：「还没有安装应用」+「浏览商店」；无结果：「没有符合条件的应用」+「清除筛选」 |
| 主操作 | 全部禁用；文案随状态：打开 / 取消安装 / 更新 / 更新中 / 启用 / 修复 |
| 注册表路径 | `platform.RegistryPath()` → `{DataDir}/apps/registry.json` |
| 注册表格式 | `{"apps": [{id, name, version, size, source, category, summary, release_notes, status, last_opened}]}` |
| 注册表容错 | 缺文件为空注册表；JSON 损坏返回错误并保持空注册表；`id` / `name` 为空跳过；未知状态转「损坏」；未安装条目跳过 |

状态矩阵：

| 状态 | 进入启动器 | 主操作 | 颜色 |
| --- | --- | --- | --- |
| 未安装 | 否 | 打开 | 次要文字 |
| 安装中 | 是 | 取消安装 | 强调色 |
| 已安装 | 是 | 打开 | 次要文字 |
| 运行中 | 是 | 打开 | 成功色 |
| 可更新 | 是 | 更新 | 强调色 |
| 更新中 | 是 | 更新中 | 强调色 |
| 已禁用 | 是 | 启用 | 危险色 |
| 损坏 | 是 | 修复 | 危险色 |

## 4. 优先级评估与实施顺序

结论：**先状态色与纯逻辑，再商店与启动器视图，最后壳装配与文档**。启动器依赖注册表契约，放在商店之后、壳装配之前。

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | `ui` 状态色 + `store` 数据与筛选 | 纯逻辑，表驱动测试成本低，先稳定数据契约 |
| P0 | App Store 页面与视图测试 | 用真实状态验证搜索、筛选、选中与空状态 |
| P0 | 状态矩阵、注册表读取、启动器筛选与排序 | 数据契约先行，避免 UI 依赖伪造数据 |
| P0 | 启动器网格、双标签与空状态 | 用户可见主路径 |
| P0 | 侧栏状态位与禁用说明 | 波及 shell 布局，需与商店页面一起做视图回归 |
| P1 | `app` 装配与文档回写 | 依赖前面契约；文档必须与代码一致 |
| P1 | 自检与人工验收 | 满足 DoD |

## 7. 验收标准

- 侧栏底部右侧显示网关状态、模型与用量入口；未配置时圆点为灰色，用量入口禁用并有说明。
- 助手 / 创作占位区在网关未配置或离线时显示禁用原因；网关在线时不显示。
- 应用模块默认「已安装」；空注册表时显示「还没有安装应用」与「浏览商店」，点击可切到「发现」。
- 「发现」显示 8 条示例应用，来源标注「内置示例」；默认选中第一条并显示详情。
- 搜索「白板」只保留匹配应用；切换分类后结果与计数同步变化；无结果时显示空状态。
- 点击「清除筛选」恢复全部应用。
- 点击应用行后详情更新，选中行有橙色背景。
- 在「发现」输入搜索词并切换分类后，切到助手再切回，搜索词、分类与选中项保持不变。
- 提供有效注册表并重启后，启动器显示卡片，未安装应用不出现；卡片主操作均为禁用态。
- 启动器状态筛选、搜索与排序生效；「最近使用」按 `LastOpened` 降序，未打开过按名称。
- 状态色：运行中绿色、可更新 / 更新中橙色、已禁用 / 损坏红色；暗色主题下可读。
- 重启应用后商店与启动器状态回到默认值。
- `gofmt -l .` 无输出，`go vet ./...`、`go test ./...` 通过，`go tool mygo build` 成功。

## 8. 风险与待确认

| 编号 | 事项 | 影响 | 当前处理 |
| --- | --- | --- | --- |
| R-01 | 网关无实现，状态只能固定「未配置」 | 在线 / 离线切换无法端到端验证 | 三态与文案由纯函数单测覆盖；状态结构保持不变，接入网关时只换数据源 |
| R-02 | mygo 未暴露滚动偏移恢复 | 切换模块后列表可能回到顶部 | 004 只承诺逻辑状态，验收标准与非目标都写明 |
| R-03 | 应用清单字段仍为 `[TBD]` | 页面过早绑定字段可能返工 | 只定义展示所需字段，示例目录标注「内置示例」 |
| R-04 | 最小 960 宽时双栏空间紧张 | 列表或详情被挤压 | 侧栏 220、详情 320、间距 16、内容内边距 32；人工在最小尺寸下观察 |
| R-05 | 用量入口禁用易被当成死链接 | 用户误以为功能损坏 | 禁用态同时显示「用量将随网关接入开放」 |
| R-06 | 搜索输入框标签与可见文案可能重复 | 列表行点击目标不明确 | 输入框使用 `Label("搜索应用")`，应用行使用 `Label("打开" + 名称)`，便于测试与可访问性 |
| R-07 | macOS 未实机验证 | 侧栏底部布局与滚动行为未知 | Windows 先验收，macOS 列入人工验证清单 |
| R-08 | 安装与启动未实现 | 启动器卡片主操作不可用 | 按钮禁用并保留文案，验收明确说明 |
| R-09 | 无真实安装数据 | 默认启动器为空，无法展示已安装效果 | 验收用临时注册表 JSON 验证，不把示例数据写进代码 |
| R-10 | 注册表尚无写入方 | 用户不能通过界面添加应用 | 安装流程在后续计划负责写入；本次只读 |

## 12. 人工验收步骤（Windows）

入口：`go tool mygo dev`，或运行 `build/windows-amd64/Bowknot Agent.exe`。

1. 侧栏状态位：查看左侧导航栏底部。预期右下角显示灰点「网关未配置」、第二行「模型未配置」、第三行禁用的「用量」与「用量将随网关接入开放」；顶部有 1px 分隔线，不遮挡导航项。
2. 禁用说明：点击「助手 / Agent」与「创作」。预期标题与描述下方显示「网关未配置，配置后可启用对话与创作」；点击「设置」与「应用」不显示该提示。
3. 商店默认态：点击侧栏「应用」，再点顶部「发现」。预期标题、搜索框、四个分类按钮、结果计数「共 8 个应用」；第一条「文档工作台」选中并显示详情。
4. 搜索：在搜索框输入「白板」。预期列表只剩「灵感白板」，计数变化；详情同步切换到该应用。
5. 分类：清空搜索后点击「分类：创作」。预期只剩创作类应用；点击「分类：全部」恢复 8 条。
6. 空状态：输入不存在的关键词。预期显示「未找到匹配应用」与「清除筛选」；点击「清除筛选」恢复全部应用。
7. 选中：点击「代码浏览器」。预期详情显示版本、来源、分类、简介与更新说明；该行橙色背景。
8. 状态保留：在「发现」选择「分类：创作」并选中一个应用，切到「助手 / Agent」再切回「应用 / 发现」。预期搜索词、分类与选中项保持不变。
9. 主题：切换亮 / 暗 / 跟随系统。预期状态位、分类选中态、列表与详情在两种主题下文字可读、无闪白。
10. 最小尺寸：把窗口缩到最小（960×640）。预期侧栏状态位不溢出，商店列表与详情不被裁切，无横向滚动条。
11. 启动器默认：打开应用。预期应用模块默认「已安装」，空注册表时显示「还没有安装应用」与「浏览商店」。
12. 写入临时注册表：创建 `C:\Users\<用户>\.bowknot-agent\apps\registry.json`，内容如下，重启应用。

```json
{
  "apps": [
    {"id": "docs", "name": "文档工作台", "version": "1.4.0", "size": "12.4 MB", "source": "本地", "category": "efficiency", "summary": "笔记与文档", "status": "已安装", "last_opened": 100},
    {"id": "code", "name": "代码浏览器", "version": "3.2.0", "size": "16.8 MB", "source": "本地", "category": "developer", "summary": "浏览仓库与差异", "status": "可更新", "last_opened": 300},
    {"id": "audio", "name": "音频剪辑", "version": "1.8.0", "size": "27.3 MB", "source": "本地", "category": "creation", "summary": "裁剪与导出音频", "status": "已禁用"},
    {"id": "broken", "name": "损坏应用", "version": "0.1.0", "source": "本地", "category": "developer", "summary": "启动失败", "status": "损坏"}
  ]
}
```

13. 启动器卡片：预期 4 张卡片、3 列布局；「代码浏览器」在最前（最近使用），「损坏应用」为红色状态。
14. 筛选 / 搜索 / 排序：点「状态：可更新」只剩「代码浏览器」；搜索「音频」只剩「音频剪辑」；点「排序：最近使用」切到「名称」后顺序变化；无结果时点「清除筛选」恢复。
15. 主操作与状态保留：所有卡片按钮为禁用态，文案随状态显示「打开 / 更新 / 启用 / 修复」；在「已安装」输入搜索并选「可更新」，切到「发现」再切回，搜索与筛选保持不变。

重点观察：侧栏底部在窄宽度下是否挤压、状态点颜色是否正确、禁用入口是否明确、列表选中态与详情是否一致、启动器卡片是否被挤压、切换模块 / 标签后状态是否丢失、暗色主题下分隔线与状态色是否可见。
