## 1. 目标

### 1.1 本次交付

1. `internal/gateway` 核心：供应商配置、六类能力路由数据、加载与原子落盘、适配器注册表。
2. 密钥安全：本地主密钥 + AES-GCM 加密，界面只显示掩码，日志与错误脱敏。
3. 连接测试：OpenAI 兼容 `/models`，超时与错误分类，结果写回配置。
4. 调用客户端：`chat`（非流式与 SSE 流式）与 `embedding`，超时、重试、并发限制、路由回退。
5. 状态快照：未配置 / 在线 / 离线、当前模型、最近原因；由 `app` 注入侧栏。
6. 设置界面：设置模块新增「模型服务」页，含供应商 CRUD、测试、密钥掩码、模型维护、`chat` / `embedding` 路由与单轮对话测试。
7. 最小用量记录：JSONL 追加，记录供应商、模型、能力、token、耗时、是否估算与错误分类，不记录正文。
8. 文档回写：FR-GW-08 改为进程内、FR-GW-05 重试次数落定、FR-GW-03 加密方式说明。
9. 单元测试、自检与人工验收步骤。

### 1.2 非目标

- 不做助手对话界面、多 Agent、记忆与任务中心（007+）。
- 不做图片、视频、语音生成及生成任务队列。
- 不做用量面板、费用价目表与预算告警（FR-COST-01 / 02，P1）；用量只写文件。
- 不做 Anthropic、Gemini 等原生协议；不开放供应商类型扩展。
- 不做网关 HTTP 服务、独立子进程与本地令牌。
- 不做系统凭据库（Windows DPAPI / macOS Keychain）。
- 不做流式 UI；流式只在客户端实现并由单测覆盖，等 007 对话界面接入。
- 不做开发者验证环境、应用图标、更新与远程商店。
- 不做 macOS 实机验收，Windows 先验收。

## 2. 前置状态与 mygo API 核实

005 已交付安装、WebApp 窗口、能力集与卸载；侧栏状态位仍固定「网关未配置」，「用量」入口禁用。`internal/gateway` 与 `internal/settings` 均为空，设置模块仍是 003 的占位卡片。

| 能力 | mygo 0.6.4 结论 | 影响 |
| --- | --- | --- |
| 文本输入 | `ui.TextInput(c, *string)`，`Element.Password()` 可隐藏内容 | 密钥输入用密码模式 |
| 下拉选择 | `ui.Select(c, *string, []string)` | 供应商类型、模型与路由选择 |
| 复选 | `ui.Checkbox(c, *bool, label)` | 供应商启用开关 |
| 模型表单 | `ui.TextInput`、`ui.Checkbox` 组合 | 逐模型填写 ID、上下文长度、最大输出、图片与工具支持 |
| 标签与弹窗 | `ui.Tabs`、`ui.Modal`、`mygo.Dialog.Message` | 设置页分区与删除确认 |
| 异步回调 | `mygo.RunOnMain(func())` | 网络测试与调用结果回到主线程更新视图 |
| 重绘 | `Window.Invalidate()` | 配置或状态变化后刷新主窗口 |
| HTTP 服务 | 无内置服务端 API，也不需要 | 客户端用标准库 `net/http` |
| 流式响应 | 无专用 API | 自行解析 `text/event-stream` |
| 本地路径 | `platform.DataDir()` / `SettingsPath()` | 网关目录由 `platform` 统一提供 |

关键结论：设置页所需的输入、下拉、复选、多行与确认弹窗均已具备；网关只需要 HTTP 客户端与后台 goroutine，不需要 mygo 提供额外能力。

## 3. 设计规格

### 3.1 分层与扩展点

```text
internal/gateway/
  config.go      # Provider、Capability、Route、Config、校验、加载与保存
  secret.go      # 主密钥、AES-GCM 加密文件、掩码
  errors.go      # 错误分类与重试判定
  adapter.go     # Adapter 接口与注册表
  openai.go      # OpenAI 兼容适配器：models / chat / embeddings / SSE
  router.go      # 能力路由解析与回退
  service.go     # 门面、状态快照、并发限制、用量
  usage.go       # JSONL 用量记录与轮转
internal/settings/
  page.go        # 设置模块「模型服务」页
  page_test.go
```

| 项 | 规格 |
| --- | --- |
| 依赖方向 | `internal/settings → internal/gateway`；`internal/gateway` 只依赖标准库与 `internal/platform`，不依赖 `ui` / `shell` / `app` |
| 门面 | `gateway.Service` 对 `app` 与 `settings` 暴露全部操作；内部结构不导出可变状态 |
| 适配器 | `Adapter` 按供应商 `type` 注册；006 只注册 `openai`，后续协议新增适配器即可 |
| 扩展点 | 若未来需要外部访问，新增 HTTP adapter 包装同一 `Service`，核心与调用方不改 |
| 线程 | 配置读写加锁；网络调用在锁外；视图只读快照，不直接做 IO |
| 测试替身 | `settings.Page` 依赖窄接口 `Gateway`，视图测试注入替身，不发真实请求 |

`Adapter` 契约：

```go
type Adapter interface {
    Type() string
    Test(ctx context.Context, p Provider, key string) (TestResult, []string, error)
    Chat(ctx context.Context, p Provider, key string, req ChatRequest) (ChatResponse, error)
    Embed(ctx context.Context, p Provider, key string, req EmbedRequest) (EmbedResponse, error)
}
```

### 3.2 供应商配置 v1

配置位于 `{DataDir}/gateway/providers.json`：

```json
{
  "schema": 2,
  "providers": [
    {
      "id": "p-1a2b3c4d",
      "name": "OpenAI",
      "type": "openai",
      "base_url": "https://api.openai.com/v1",
      "enabled": true,
      "models": [
        {
          "id": "gpt-4o-mini",
          "context_window": 128000,
          "max_output_tokens": 16384,
          "supports_images": true,
          "supports_tools": true
        }
      ],
      "last_test": {
        "ok": true,
        "kind": "models",
        "message": "12 个模型可用",
        "at": 1790000000
      }
    }
  ],
  "routes": {
    "chat": [{"provider": "p-1a2b3c4d", "model": "gpt-4o-mini"}],
    "embedding": []
  }
}
```

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `schema` | 是 | 必须为 `2`；其他版本（含旧的 `1` 模型名数组）按空配置启动并记录错误，不覆盖原文件；未发布 1.0，不做迁移 |
| `id` | 是 | `p-` + 8 位十六进制，内部生成，界面不展示 |
| `name` | 是 | 1–64 字符，去首尾空格后非空 |
| `type` | 是 | 006 只接受 `openai`；未知类型在加载时标记为不支持，禁止测试与调用 |
| `base_url` | 是 | `http` / `https`；不允许 userinfo、查询串与片段；去掉末尾 `/`；须包含 API 版本路径（如 `/v1`） |
| `enabled` | 是 | 停用后不参与测试、调用与路由 |
| `models` | 是 | 0–100 条；每条 `id` 1–128 字符并去重，`context_window` / `max_output_tokens` 为 0–10000000 的整数且输出不得大于上下文，`supports_images` / `supports_tools` 为布尔；0 表示未知；为空时可由连接测试填入（仅 `id`） |
| `last_test` | 否 | `ok`、`kind`（`models`）、`message`（≤200 字符，不含密钥）、`at`（Unix 秒） |
| 未知字段 | — | 忽略，保证向后兼容 |
| 路由键 | — | `chat` / `image` / `video` / `tts` / `asr` / `embedding`；未知键忽略 |
| 路由目标 | — | `{provider, model}`，供应商必须存在；`model` 必须是该供应商某个模型的 `id` |
| 落盘 | — | 临时文件 + `os.Rename` 原子替换；失败返回错误并保留内存状态 |
| 容错 | — | 文件缺失为空配置；JSON 损坏或 schema 未知时记录日志并**只读空配置**，不写回损坏文件 |

校验错误按字段返回，设置页逐条显示，不弹系统对话框。

### 3.3 密钥存储

| 项 | 规格 |
| --- | --- |
| 目录 | `{DataDir}/gateway/`，目录权限 `0700` |
| 配置 | `providers.json`，不含任何密钥 |
| 密文 | `credentials.bin`，明文为 `{"<provider-id>": "<key>"}` 的 JSON |
| 主密钥 | `master.key`，32 字节随机数，文件权限 `0600`；缺失时首次启动生成 |
| 加密 | AES-256-GCM；文件格式 `BKG1` + 12 字节 nonce + 密文；写入前重新随机 nonce |
| 解密失败 | 视为密钥不可用：记录日志、清空内存密钥、保留配置并提示重新填写 |
| 掩码 | 长度 ≥ 8 时显示 `••••` + 末 4 位；更短时显示 `已配置`；未配置显示 `未配置` |
| 编辑 | 密钥输入框留空表示保留旧值；填写后覆盖；删除供应商同时删除密文条目 |
| 明文边界 | 仅在保存瞬间存在于设置页输入框与服务内存；保存 / 取消后清空输入框，日志与错误永不输出明文 |
| 限制说明 | 主密钥与密文同目录，属于防误读而非强隔离；后续可替换系统凭据库（R-01） |

### 3.4 连接测试与错误分类

| 项 | 规格 |
| --- | --- |
| 请求 | `GET {base_url}/models`，`Authorization: Bearer <key>`（无密钥时不带） |
| 成功 | 2xx 且 JSON 可解析；返回模型 ID 列表（去重，最多 100） |
| 自动填充 | 供应商 `models` 为空时用返回列表填充；非空时保留用户列表，仅在结果里显示数量 |
| 超时 | 整体 15 秒；连接与响应头 10 秒 |
| 写回 | 无论成功失败都写 `last_test`，并原子保存配置 |
| 结果展示 | 「成功 · N 个模型 · 时间」或「失败 · 分类 · 原因」；原因不含 URL 凭据与密钥 |
| 错误分类 | 见下表 |

| 分类 | 触发 | 重试 | 回退到下一目标 |
| --- | --- | --- | --- |
| `auth` | 401 / 403 | 否 | 是 |
| `quota` | 429 | 否 | 是 |
| `moderation` | 响应体含内容审核错误码 | 否 | **否** |
| `model` | 400、404、模型不存在或参数非法 | 否 | 是 |
| `network` | DNS、连接失败、TLS、连接超时 | 是（最多 2 次） | 是 |
| `timeout` | 响应超时或读取超时 | 是（最多 2 次） | 是 |
| `server` | 5xx | 是（最多 2 次） | 是 |
| `internal` | 其余本地错误 | 否 | 否 |

重试间隔 500ms、1500ms，可被 `context` 取消；内容审核不重试、不切换目标。

### 3.5 调用客户端

| 项 | 规格 |
| --- | --- |
| 端点 | `{base_url}/chat/completions`、`{base_url}/embeddings`；由适配器拼接，业务不手写 |
| Chat 请求 | `model`、`messages`（role / content）、`max_tokens`（可选）、`temperature`（可选）、`stream` |
| Chat 响应 | 内容、实际模型、token 用量（可能缺失）、耗时、供应商 ID |
| 流式 | `stream: true`，逐行解析 `data:`；拼接 `choices[0].delta.content`；`[DONE]` 结束；忽略空行与注释行 |
| 流式取消 | 调用方取消 `context` 即停止读取并关闭响应体 |
| Embedding | 输入单条或多条文本，返回向量与 token 用量 |
| 超时 | 非流式整体 60 秒；流式整体 120 秒，两次数据间隔超过 30 秒视为超时 |
| 并发限制 | 每个供应商最多 4 个在途请求，用带缓冲信号量排队；等待受 `context` 约束 |
| 重试 | 仅 `network` / `timeout` / `server`，最多 2 次；其余分类不重试 |
| 回退 | 按路由顺序；`moderation` 与 `internal` 不回退 |
| 用量 | 每次真实调用（含测试调用）写一条记录，详见 3.8 |

`chat` 与 `embedding` 在 006 只有设置页单轮测试一个调用方；流式能力仅由单测覆盖，界面不展示流式输出。

### 3.6 能力路由与回退

| 项 | 规格 |
| --- | --- |
| 能力 | `chat` 对话、`image` 图片、`video` 视频、`tts` 语音合成、`asr` 语音识别、`embedding` 向量 |
| 数据 | 每类为有序目标列表，第一项为主目标，其余为备用 |
| 006 界面 | 只开放 `chat` 与 `embedding` 两类；其余四类在页面显示为「随对应模块接入后开放」，不可编辑 |
| 默认值 | 保存第一个启用供应商时，若 `chat` / `embedding` 为空则自动取该供应商的第一个模型填入；后续保存不自动覆盖 |
| 校验 | 目标必须指向已存在供应商且模型在列表中；保存时清理指向已删除供应商的目标 |
| 停用供应商 | 路由保留但不参与解析；全部目标不可用时该能力视为未配置 |
| 解析 | 过滤停用与不支持类型的供应商后按顺序尝试，成功即返回 |
| 未配置 | `chat` 无可用目标时，侧栏显示「模型未配置」，对话测试禁用并说明 |

### 3.7 状态快照

```go
type State int

const (
    StateNotConfigured State = iota
    StateOnline
    StateOffline
)

type Snapshot struct {
    State     State
    Model     string
    Reason    string
    UpdatedAt time.Time
}
```

| 场景 | 状态 | 说明 |
| --- | --- | --- |
| 无供应商或无启用供应商 | 未配置 | 侧栏灰点 |
| 有启用供应商，从未测试或调用 | 离线 | 原因「尚未连接测试」，提示用户先测试 |
| 最近一次测试或调用成功 | 在线 | 侧栏绿点 |
| 最近一次测试或调用失败 | 离线 | 原因取错误分类文案 |
| 用户停用 / 删除最后一个供应商 | 未配置 | 立即重算 |
| 启动 | 读取持久化的 `last_test` 计算，不发网络请求 | 避免启动阻塞与意外计费 |

- `Model` 取 `chat` 主目标；无主目标时为空，侧栏显示「模型未配置」。
- `Reason` 只在设置页展示；侧栏保持 004 的三态文案。
- 快照变化通过 `Service.OnSnapshot` 回调给 `app`，`app` 用 `mygo.RunOnMain` 更新 `shell.Status` 并 `Invalidate`。
- `app` 负责把 `gateway.State` 映射为 `shell.GatewayState`，网关包不依赖 shell。

### 3.8 用量记录

| 项 | 规格 |
| --- | --- |
| 文件 | `{DataDir}/gateway/usage.jsonl`，目录 `0700`，文件 `0600` |
| 时机 | 每次真实模型调用结束后写一条；连接测试不写 |
| 字段 | `time`、`origin`（`settings` / 后续模块名）、`provider_id`、`provider_name`、`model`、`capability`、`input_tokens`、`output_tokens`、`usage_estimated`、`duration_ms`、`status`（`ok` / `error`）、`error_code` |
| 估算 | 供应商未返回 token 用量时 `usage_estimated=true`，token 记 0；不推断 |
| 费用 | 006 不计算金额，不写费用字段；价目表与金额随 FR-COST-01 接入 |
| 禁止 | 不记录提示词、回复正文、密钥、完整 URL 与请求头 |
| 写入 | 互斥追加，`O_APPEND`；写失败只记录日志，不影响调用结果 |
| 轮转 | 超过 5 MiB 时改名为 `usage-<Unix秒>.jsonl`，最多保留 5 个历史文件，超出删除最旧 |
| 读取 | 提供按时间倒序读取最近 N 条与统计总数的只读方法，供后续用量面板与测试使用 |

### 3.9 设置界面

设置模块由 `app` 注入 `settings.Page`，页面常驻，切换模块保留编辑与测试状态。

| 区域 | 内容 |
| --- | --- |
| 页头 | 标题「设置」，副标题「模型服务与网关」；当前网关状态、当前模型与最近原因 |
| 供应商列表 | 每行：名称、类型、地址、启用复选框、掩码密钥、最近测试结果、操作「编辑 / 测试 / 删除」；底部「添加供应商」 |
| 编辑器 | 内联面板：名称、类型（Select，仅「OpenAI 兼容」）、地址、密钥（密码输入，留空保留）、模型表单、启用；「保存 / 取消 / 测试」 |
| 模型表单 | 「添加模型」追加一行：模型 ID、上下文长度、最大输出、支持图片、支持工具调用、删除；空行保存时跳过，半填行报错；数值留空表示未知；列表摘要显示首个模型的元信息 |
| 连接测试 | 仅对已保存配置生效；未保存修改时提示先保存；进行中按钮显示「测试中…」并禁用；结果与时间写回列表 |
| 路由 | `chat` 与 `embedding` 各一行：主目标下拉（供应商 · 模型）与备用目标列表，可添加 / 移除；「保存路由」；其余四类只读说明 |

### 3.10 日志与安全

- 日志字段化输出供应商 ID、分类、状态码与耗时；不输出密钥、`Authorization`、请求体、回复正文。
- URL 只记录 scheme + host + path，不记录 userinfo、查询串与片段。
- 错误文案面向用户，包含分类与可操作建议，不包含宿主绝对路径。
- 配置文件与密文文件不进入版本库；`build/`、`.mygo/` 仍保持忽略。
- 网关不监听端口，WebApp 无法直接访问；WebApp 与网关的隔离边界在 006 不变。

## 4. 优先级评估与实施顺序

结论：**先配置与密钥，再适配器与客户端，然后门面与状态，最后设置界面与装配**。配置契约与加密是纯逻辑，测试成本低；界面依赖门面稳定。

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | 配置模型、校验、加载 / 保存、原子写 | 数据契约先行，界面与客户端都依赖 |
| P0 | 主密钥、AES-GCM、掩码 | 安全边界必须先于真实调用 |
| P0 | 错误分类、OpenAI 适配器、连接测试 | 验证供应商可用性的最小路径 |
| P0 | Chat / Embedding 客户端、重试、并发限制、SSE | 网关核心能力，007 直接复用 |
| P0 | 路由解析与回退、状态快照 | 侧栏与设置页依赖 |
| P0 | 用量记录与轮转 | FR-GW-06 最小实现 |
| P0 | 设置页供应商 CRUD、测试、路由、对话测试 | 用户可见主路径 |
| P1 | `app` 装配、状态注入、文档回写 | 满足 DoD |
| P1 | 人工验收 | 真实供应商与界面行为无法自动化 |

## 7. 验收标准

- 无供应商时，侧栏为灰点「网关未配置」「模型未配置」；设置页显示空状态与「添加供应商」。
- 新增供应商并保存后，密钥显示掩码；编辑时留空保存不会清空密钥；删除后密文条目与路由引用一并清理。
- 配置目录含 `providers.json`、`credentials.bin`、`master.key`；`providers.json` 中不出现任何明文密钥。
- 连接测试成功：状态变绿点「网关在线」，显示模型数量与时间；模型列表为空时自动填入。
- 连接测试失败（错误密钥 / 404 / 超时）：配置保留，状态变红点「网关离线」，错误分类与原因可见；日志无密钥。
- 单轮对话测试成功：显示回复、实际模型、耗时与 token；`usage.jsonl` 追加一条 `origin=settings` 记录。
- 供应商不返回 token 用量时，记录 `usage_estimated=true`，不虚构 token。
- 配置 `chat` 主目标与备用目标后，主目标不可用时可回退到备用；内容审核错误不回退、不重试。
- 重启应用后供应商、掩码密钥、路由、最近测试结果与侧栏状态保持不变。
- 设置页在亮 / 暗主题与 960×640 最小窗口下可读、无横向溢出；测试与对话进行中界面保持响应。
- 页面与日志中不出现明文密钥；错误信息不包含宿主绝对路径。
- `gofmt -l .` 无输出，`go vet ./...`、`go test ./...` 通过，`go tool mygo build` 成功。

## 8. 风险与待确认

| 编号 | 事项 | 影响 | 当前处理 |
| --- | --- | --- | --- |
| R-01 | 主密钥与密文同目录，且 Windows 文件权限不等同于 0600 | 加密只防误读，不防有本机访问权限的攻击者 | 文档写明限制；系统凭据库列为后续可选升级 |

## 11. 人工验收步骤

验收入口：`go tool mygo build` 后运行 `build/windows-amd64/Bowknot Agent.exe`，或开发时 `go tool mygo dev`。所有网关文件位于 `C:/Users/<用户>/.bowknot-agent/gateway/`。

1. 空状态与侧栏
   - 操作：启动后进入左侧「设置」。
   - 预期：页头显示「设置」「模型服务与网关」、灰点「网关未配置」「当前模型：模型未配置」；页面显示「还没有配置模型服务」与「添加供应商」；侧栏底部为灰点「网关未配置」「模型未配置」，禁用的「用量」旁显示「用量面板将在后续计划开放」。
   - 重点：无横向溢出、无控制台报错。

2. 新增供应商与模型表单
   - 操作：点「添加供应商」，名称填 `OpenAI`，地址填 `https://api.openai.com/v1`（或本地 Ollama `http://127.0.0.1:11434/v1`，密钥留空），密钥填入有效值；点「添加模型」，填模型 ID `gpt-4o-mini`、上下文长度 `128000`、最大输出 `16384`，勾选「支持图片」与「支持工具调用」；再点「添加模型」留空；勾选启用，点「保存」。
   - 预期：编辑器关闭，列表出现该供应商；模型摘要显示「模型 1 个 · gpt-4o-mini · 上下文 128000 · 输出 16384 · 图片 · 工具」；密钥显示 `••••` + 末 4 位（本地服务显示「未配置」）；侧栏仍为「网关离线」（尚未测试），当前模型取 `chat` 主目标。
   - 预期（校验）：只填上下文长度不填模型 ID，或最大输出大于上下文长度，点「保存」时面板不关闭并在下方显示对应错误。
   - 重点：保存后输入框不再保留明文密钥；空模型行不写进配置；「删除模型 N」只移除该行。

3. 配置文件与密钥
   - 操作：打开 `~/.bowknot-agent/gateway/`，查看 `providers.json`、`credentials.bin`、`master.key`。
   - 预期：三个文件存在；`providers.json` 的 `schema` 为 `2`，`models` 是对象数组，且不含任何明文密钥；`credentials.bin` 以 `BKG1` 开头，直接文本查看看不到密钥。
   - 预期（旧配置）：开发期若留有 `schema: 1` 的旧文件，应用按空配置启动并记录错误；删除该文件后重新添加即可，不提供迁移。
   - 重点：截图或复制 `providers.json` 时不应出现 sk- 开头的字符串。

4. 连接测试
   - 操作：点该供应商「测试」。
   - 预期（成功）：按钮短暂显示「测试中…」后恢复；列表显示「成功 · N 个模型可用 · 时间」；模型为空时自动填入返回模型（≤100）；侧栏变绿点「网关在线」并显示 `chat` 主目标模型。
   - 预期（失败，如错误密钥）：列表显示「失败 · 鉴权 · …（HTTP 401）」；侧栏红点「网关离线」；配置保留。
   - 重点：界面在请求期间保持响应；错误文案不含密钥与绝对路径。

5. 编辑与删除
   - 操作：点「编辑」，确认模型行回填上下文长度、最大输出与两个勾选；把最大输出改为 `4096`、取消「支持工具调用」，密钥留空直接保存；再点「删除」，先点「取消删除」，随后重新删除并「确认删除」。
   - 预期：留空保存后原密钥仍为原掩码；模型摘要显示新的输出长度且不再有「工具」；取消删除不改变列表；确认后供应商消失，相关 `chat` / `embedding` 路由一并清空，侧栏回到「网关未配置」。
   - 重点：删除确认文案明确会清除密钥。

6. 能力路由
   - 操作：配置至少两个模型（或两个供应商），在「对话（chat）」把主目标切到另一个模型，添加一个备用目标并「保存路由」；「向量（embedding）」同样可保存。
   - 预期：主目标显示「供应商 · 模型」；备用按顺序显示，可「移除」；保存后显示「路由已保存」；图片 / 视频 / 语音四类只显示「随对应模块接入后开放」，不可编辑。
   - 重点：停用供应商后其目标不参与调用；删掉供应商后其路由不残留。

7. 单轮对话测试
   - 操作：在「对话测试」确认目标为 `chat` 主目标，输入提示词（如「你好」），点「发送」。
   - 预期：按钮显示「发送中…」，随后显示回复正文、实际模型、耗时与「输入 X · 输出 Y token」（供应商未返回用量时显示「token 用量未返回」）；侧栏变绿点「网关在线」。
   - 预期（错误目标）：显示「鉴权 / 配额 / 模型 / 网络 / 超时 / 服务端 …」分类与原因，不回退到其他供应商的错误不切换。
   - 重点：这一步会真实调用模型并产生费用；`usage.jsonl` 追加一条 `origin=settings` 记录，且不含提示词与回复正文。

8. 用量文件
   - 操作：完成第 7 步后查看 `~/.bowknot-agent/gateway/usage.jsonl`。
   - 预期：每行一条 JSON，含 `provider_name`、`model`、`capability`、token、`usage_estimated`、`duration_ms`、`status`；无提示词、回复、密钥、完整 URL。
   - 重点：连接测试不写用量，只有真实对话写入。

9. 重启持久化
   - 操作：退出并重新启动应用，再进入设置。
   - 预期：供应商、掩码密钥、模型、路由与最近测试结果均保留；侧栏状态按上次测试结果为在线 / 离线；启动不自动发网络请求。
   - 重点：启动无卡顿、无计费请求。

10. 主题与最小窗口
    - 操作：切换亮 / 暗主题；把窗口缩到最小（960×640），滚动设置页。
    - 预期：两种主题下文字、边框与按钮可读；页面单列滚动，无横向溢出；「测试中…」「发送中…」期间界面可滚动、可切换模块，回来后状态保留。
    - 重点：暗色下按钮与危险文案对比度，滚动条不遮挡内容。

11. 安全边界
    - 操作：查看应用日志与上述文件。
    - 预期：日志不出现密钥、`Authorization`、提示词、回复正文与完整请求 URL；页面任何位置不出现明文密钥。
    - 重点：网络失败日志只显示分类与状态码。
